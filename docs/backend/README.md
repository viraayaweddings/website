# Backend

Server logic shared by the public site and the admin panel. It runs inside one
Vercel serverless function; there is no separate worker process.

**Entry points:** `app/[[...path]]/route.ts` for public traffic, and the App
Router for `/admin`, `/api` and `/media`.

## Request handling order

Inside the catch-all, in order:

1. **App-owned prefix** → hand to the App Router. Only these; a public path has
   no App Router page behind it, and delegating one recurses.
2. **Redirect** → 301 for a retired URL.
3. **Database render** → shell from `page_templates`, filled by injection.
4. **Original markup** → fetched back through the origin, then injected.
5. **404** → the site's own `404.html`.

See [Architecture](../01-architecture.md#request-flow) for how Vercel routes a
request before it reaches any of this.

## HTMLRewriter on Node

Every HTML transform here is written against Cloudflare's streaming
`HTMLRewriter`. Vercel's Node runtime has no such global, so
`worker/html-rewriter.ts` installs one backed by `html-rewriter-wasm` — the same
lol-html engine, compiled to WebAssembly. Handlers work unchanged and markup a
handler does not touch still round-trips byte-for-byte, which the rich-text
sanitiser depends on.

The package must stay out of the bundle. See
[Configuration](./../09-configuration.md#viteconfigts).
